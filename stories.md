# User Stories & Tasks

### Evidence
* **User Story 1:** *As a Khayelitsha resident, I want to report a sewage overflow using my mobile phone with geotagging, so that municipal maintenance can locate the hazard quickly.*[cite: 2, 3, 11]
  * Task 1.1: Build React Native Expo intake form[cite: 3].
  * Task 1.2: Integrate Google Maps API & Expo Location[cite: 3].
* **User Story 2:** *As a municipal admin, I want to view reported pipe bursts sorted by priority on a dashboard, so that field teams can be dispatched.*[cite: 2, 3, 11]
  * Task 2.1: Design dashboard card layouts in Figma[cite: 4].
  * Task 2.2: Implement Supabase backend API queries[cite: 3].

### Reflection
Shifting from traditional requirements specifications to user story mapping changed how I approach software design[cite: 3]. Writing from the end-user's viewpoint forced us to strip away unnecessary technical complexity and concentrate strictly on core value delivery[cite: 2, 3].
